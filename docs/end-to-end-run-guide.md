## 4. Step-by-Step Clinical Walkthrough (Cold Start $\rightarrow$ AI Assessment)

Here is the exact step-by-step path to complete an encounter and trigger the AI assessment:

---

### Step 1: Sign In as a Frontline Health Worker (`LoginScreen`)
When the app launches for the first time, you are greeted by the Worker Sign-In screen.

1. **Enter Your Name:** Type any name (e.g., `Asha Devi` or `Sister Mary`).
2. **Select Your Role:** Tap on your cadre:
   - **ASHA Worker** *(Community health activist)*
   - **Nurse** *(Staff nurse)*
   - **Compounder** *(PHC pharmacy & vitals assistant)*
3. **Tap "Sign In":**
   - *Security Note:* If your test device or emulator has a screen lock (PIN, Pattern, or Fingerprint) set up, a system `BiometricPrompt` will appear. Confirm your PIN/fingerprint to unlock the session.
4. **Result:** You will land on the **Home Dashboard**.

---

### Step 2: Home Dashboard (`HomeScreen`)
The dashboard displays today's roster, network status, and operational controls.

1. Locate the primary action button: **"Register new patient"** (or tap **"New Consultation"**).
2. Tap the button to start a new patient visit.
3. **Result:** You will be taken to the **ABHA Patient Onboarding** screen.

---

### Step 3: ABHA Identity Verification (`AbhaEntryScreen`)
The Ayushman Bharat Digital Mission (ABHA) gateway allows identity linking.

You have three options:
- **Option 1 (Fast Demo): Tap "Create ABHA":**
  - Enter a sample name (e.g., `Ramesh Kumar`), gender, and year of birth.
  - Tap **"Create Profile"**.
  - A brief simulated redirect screen (`REDIRECTING...`) will mint a canonical 14-digit ABHA ID (`12-3456-7890-1234`).
  - The app will automatically advance to registration with all fields pre-filled!
- **Option 2: Tap "Login with ABHA":**
  - Enter an existing 14-digit ABHA ID.
  - Enter OTP `123456` on the OTP verification screen.
- **Option 3: Tap "Skip for now":**
  - Skips ABHA linking and opens a blank Patient Registration form directly.

---

### Step 4: Patient Registration (`RegisterScreen`)
Ensure basic patient demographics are recorded:

1. **Full Name:** `Ramesh Kumar`
2. **Date of Birth / Age:** `38` years old
3. **Biological Sex:** `Male`
4. **Mobile Number:** Enter any 10-digit number (e.g., `9876543210`).
5. **Address / Village:** `Bagru Village`, Pincode `303007`.
6. **Tap "Register Patient":**
   - An offline-resilient 12-character unique alphanumeric ID (e.g., `X7K2M9P4L1W8`) is allocated immediately.
7. **Result:** You are taken to the **Patient Summary** screen.

---

### Step 5: Patient Summary & Encounter Start (`PatientSummaryScreen`)
Notice the persistent header banner displaying the patient's name and UID across the top of the screen.

1. Review the patient demographics card.
2. Tap the prominent button: **"Start Consultation"** (or **"New Visit"**).
3. **Result:** Advances to the **Digital Consent Gate**.

---

### Step 6: Informed Consent Checkpoint (`ConsentScreen`)
To comply with medical ethics and regulatory standards, patient consent must be recorded prior to physical evaluation.

1. A bilingual statement is displayed:  
   *"मरीज़ की सहमति ली गई / Informed consent obtained for clinical assessment"*.
2. Tap the **checkbox** to confirm consent.
3. Tap **"Continue"**.
4. **Result:** Advances to the **Vitals & Ailments** screen (`CompounderScreen`).

---

### Step 7: Vitals Acquisition & Ailments (`CompounderScreen`)
Record the patient's objective physiological measurements and specific concerns.

#### A. Record Vitals:
Enter plausible clinical values into the form:
- **Systolic BP:** `125` mmHg
- **Diastolic BP:** `82` mmHg
- **Pulse Rate:** `74` bpm
- **Oxygen Saturation ($\text{SpO}_2$):** `98` %
- **Temperature:** `98.6` °F
- **Blood Glucose (optional):** `110` mg/dL
- **Capture Method:** Select `Digital Monitor` or `Manual Cuff` from the dropdown.

> [!CAUTION]
> **Safety Red-Flag Feature:** Do **NOT** set $\text{SpO}_2 < 90\%$ or Systolic BP $\ge 180\text{ mmHg}$ unless you want to trigger the **Emergency Override Alert**. Tripping these values immediately halts routine consultation and prompts an urgent hospital transfer.

#### B. Record Symptoms / Ailments:
1. Under the **Ailments** section, tap to add a complaint:
   - **Type:** Non-Measurable
   - **Description:** `Persistent dry cough and mild headache`
   - **Duration:** `3 days`
   - **Severity:** Adjust slider to `5 / 10`
   - **Visibility:** Leave as `Public` *(or toggle `Private` to see the patient privacy handoff modal)*.
2. Tap **"Continue"**.
3. **Result:** Advances to **Medical Background**.

---

2. Tap **"Continue"**.
3. A **Review Summary Dialog** will appear to prevent accidental submission.
4. Tap **"Save & Continue"**.

This is the core clinical narrative capture screen.

2. **Onset & Factors:** Select onset (`Sudden` or `Gradual`).
3. *(Optional Features to try):*

   - **Microphone Icon:** Tap to test the on-device, air-gapped speech recognition dictation.
4. Tap **"Review & Send"**.
5. A confirmation dialog will summarize the consultation data to mitigate automation bias.
6. Tap **"Confirm & Send"**.
7. **Result:** Advances to the **Sending Screen**.

2. Transmitting signals (vitals, age, gender, symptom text) to the AI decision support engine.

4. Automatically transitions once processing completes (typically 1 to 2 seconds).

## 6. Optional: Running Mode 2 (Full-Stack Connected Setup)

If you wish to run with the live Docker backend and local ML classifier rather than the offline fallback:

### 1. Start the Backend Containers
In a terminal on your host machine:
```bash
cd /media/sandesh/extra-ssd/AndroidWork/SaMDApp/backend
docker compose up -d db api
```
Verify the API is running by visiting `http://localhost:8080/health` in your browser.

### 2. Configure Host Network Address
1. Find your host workstation's local Wi-Fi / Ethernet IP address:
   ```bash
   ip -4 addr show | grep inet
   # Example: 192.168.1.50
   ```
2. In `local.properties`, update the backend address:
   ```properties
   # Use your machine's LAN IP if testing on physical phone:
   BACKEND_BASE_URL=http://192.168.1.50:8080/
   
   # Or if testing on the standard Android Emulator, you can use:
   # BACKEND_BASE_URL=http://10.0.2.2:8080/
   ```
3. Rebuild the app (`./gradlew installDevDebug`). The app will now submit assessments through the live backend proxy!

## 7. Troubleshooting & FAQs

| Issue | Cause | Solution |
| :--- | :--- | :--- |
| **"Cannot sign in — no lock screen configured"** | Android Keystore security requires a screen lock for biometric authentication. | Open Android Settings on the device/emulator $\rightarrow$ Security $\rightarrow$ Set a PIN or Pattern (e.g. `1234`). Reopen the app. |
| **App shows "Offline fallback (mock)" on the assessment screen** | The app could not reach a live ML server on the LAN, so it safely activated the built-in scenario fallback. | This is intended behavior for offline field use! The assessment works seamlessly without a server. If you want live inference, verify backend Docker containers are running and check `BACKEND_BASE_URL`. |
| **Emergency Red Alert screen appeared and won't let me continue** | Physiological tripwire was triggered (e.g., SpO2 was entered $< 90\%$ or BP $\ge 180/120$). | This is a built-in safety gate (`REQ-TRS-02`). Tap "Acknowledged" to return to Home, then start a new consultation with normal vitals (e.g., SpO2 $98\%$, BP $120/80$). |
| **Gradle build error / out of space on emulator** | Emulator internal partition full. | Run `adb shell rm -rf /data/local/tmp/*` or wipe emulator user data from the Android Studio Virtual Device Manager. |
