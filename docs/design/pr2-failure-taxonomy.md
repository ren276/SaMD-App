## 1. The device refusal vocabulary

`SlmRefusal.ENGINE_FAILED` was one value covering every way an engine can fail. Now six, plus PR-1's
identity refusal, which composes rather than duplicating.

| Value | Fires on | Retryable |
|---|---|---|
| `ENGINE_UNREACHABLE` | no route, DNS, connection refused | yes, soon. **The normal case** |
| `ENGINE_TIMEOUT` | reached, no answer inside the budget | yes |
| `ENGINE_UNAVAILABLE` | circuit open, or model not loaded | yes, later, not immediately |
| `ENGINE_REJECTED_INPUT` | any 4xx: over token limit, bad template version, declined `model_id` | **no, not unchanged** |
| `ENGINE_FAILED` | 5xx, OOM, malformed envelope, anything unclassifiable | yes, cause unknown |
| `OUTPUT_TRUNCATED` | `finish_reason` was `length` or `error`, or absent | yes |
| `SERVED_MODEL_MISMATCH` (PR-1) | envelope names an artifact this build was not verified against | no |

**Why it mirrors `KernelCallOutcome` rather than inventing.** That backend enum already answers this
exact question for the classifier hop, and its own docstring makes the argument for the granularity:
folding unreachable and erroring into one bucket "would throw that distinction away at the one place
it is cheap to keep". One vocabulary across both model hops means an operator reading a
`kernel_call_log` row and an SLM row is reading the same words. There are now **four** vocabularies
in this system touching failure (`SyncState`, `KernelCallOutcome`, `InferenceSource`, `SlmRefusal`);
adding a fifth set of names for the same distinctions would have been the worst available option.

**`ENGINE_REJECTED_INPUT` versus `SERVED_MODEL_MISMATCH`**, since they are easy to confuse and both
involve a model id. The first is the service **refusing to serve** what was asked for, before
generating, as a 4xx. The second is the service having **served something else** and said so in the
response. Request side and response side. Both exist; neither is redundant.

**`OUTPUT_TRUNCATED` is the one that earns its own paragraph.** A truncated readback passes the
sanitizer, because truncation is not a control token, and it passes the output grounding gate **by
construction**, because a cut-off restatement of an approved record introduces no drug name and no
numeral the record did not already carry, so `outputIsGrounded` returns true on it every time. It
arrives over a 200. The `finish_reason` field of the memo's §2.2 envelope is the only place in the
entire system where it is detectable. What reaches the worker if it is not caught is half a dosing
instruction read as a whole one. A missing finish reason is this refusal too: "the service did not
say whether the answer is complete" and "the answer is not complete" are the same thing from the
worker's side.

**The blanket catch became a classifier.** `engineRefusalFor(t: Throwable)` maps `SlmEngineError` to
`SlmRefusal`, with `else -> ENGINE_FAILED` so an untyped throwable still refuses: fail-closed on the
taxonomy, not only on the outcome. **The `CancellationException` rethrow is byte-identical to what
it was.**

## 2. `SlmEngine`'s contract

- **Typed failures.** New `SlmEngineError` (UNREACHABLE, TIMEOUT, UNAVAILABLE, PAYLOAD_REJECTED,
  ENGINE_ERROR, MALFORMED_RESPONSE) carried on a new `SlmEngineException`. The KDoc's old sentence,
  that a failure arrives as an exception and becomes `ENGINE_FAILED`, is replaced.
- **`finishReason(): SlmFinishReason?`** added beside PR-1's `servedModelId()`. Null is a refusal,
  not a default, and the KDoc forbids a binding from synthesising `STOP` because the HTTP status was
  200. A truncated generation returns 200.
- **The cancellation KDoc is corrected.** It promised that cancelling the collection cancels the
  generation, which §8 reinforces with "does not merely hide the surface while the CPU keeps
  burning". That was written for an on-device engine and **a remote binding cannot keep it**:
  cancelling an OkHttp call closes a socket while the GPU runs on to `max_new_tokens`, holding VRAM,
  blocking the next request on a single-worker service. What cancellation now guarantees is stated
  exactly: no further chunk is delivered, nothing more is displayed, the seam produces no result. It
  does not guarantee the work stopped. Making it true again is the **service's** obligation via
  disconnect detection, landing in PR-5.

## 3. The backend half, same commit

- **`SlmCallOutcome`** in `app/models/enums.py`, directly below `KernelCallOutcome`: SUCCESS,
  TIMEOUT, UNREACHABLE, ENGINE_ERROR, PAYLOAD_REJECTED, MALFORMED_RESPONSE, CIRCUIT_OPEN,
  PHI_REJECTED, plus **NOT_LOADED** and **TRUNCATED**.

  TRUNCATED is why this is a separate enum rather than a reuse: a classifier answers or it does not,
  a generative model can answer halfway, and TRUNCATED is a 200 with a well-formed body that must
  not be treated as a success. NOT_LOADED is the other addition: a service holding roughly 9.5 GiB
  of bfloat16 weights has an up-but-not-serving state that a classifier loading a 4.7 MB artifact at
  import time does not really have.

- **Four device `AuditAction` values**, added to the Kotlin enum and the backend mirror **in this
  same change**: `slm_readback_invoked`, `slm_readback_input_refused`,
  `slm_readback_output_suppressed`, `slm_readback_sanitizer_activity`. Not emitted yet; the seam's
  audit stage is not built. Same posture as `voice_field_*` and `referral_status_changed`: accepting
  a not-yet-emitted value now is cheap, accepting it late needs a coordinated field migration.

  Payload on all four is measured metadata only. Never the question text, never the generated text,
  never a drug name.

## 4. What a test caught that reasoning did not

Two, and the second is the better one.

**4.1 The mirror test I wrote read a value out of a prose comment.**
`AuditActionBackendMirrorTest` regexed quoted literals out of the whole Python module and reported
`rejected` as a mirror entry the device enum does not declare. The source was **the comment I had
just added to the mirror**, which contains the phrase `"rejected" maps to SyncState.FAILED`. My own
KDoc had asserted, one paragraph above the bug, that "Comments carry no quotes, so they drop out."

That was wrong in the most predictable way: the mirror file is heavily commented by design, every
entry carries its reasoning, so quoted words in prose are the **normal** case there rather than an
edge one. Fixed by stripping from an unquoted `#` to end of line before reading values, and the KDoc
now records the bug rather than the confident wrong claim.

Worth noting what this near-miss actually was. A regex that silently over-matches on a comparison
test does not fail safe: had it over-matched in the other direction, by picking up a value from a
comment on the **device** side, the two sets would have agreed for the wrong reason and the test
would have read green while the coupling was broken. The non-emptiness assertions were written for
exactly that failure mode and were not enough on their own; stripping comments is what actually
closes it.

**4.2 The existing backend guard runs under pytest, and this repo's contributors run Gradle.**
`test_audit_actions_device.py::test_mirror_matches_the_android_source_when_reachable` already
asserts the equality **bidirectionally** by parsing `AuditLogger.kt` directly, so the brief's
"add a test if one does not already exist in that shape" is answered: one does.

But it only fires if the backend suite runs. A developer who adds an `AuditAction`, runs
`testDevDebugUnitTest` green and opens a PR gets **no signal at all**. The coupling is not a style
rule, so it should fail on whichever side the edit was made. `AuditActionBackendMirrorTest` is the
device-side mirror of that guard, plus a second test asserting every `AuditAction` value is
lower_snake_case, because the backend parser's regex is `[A-Z_]+\("([a-z_]+)"\)` and a value with a
digit or a capital would be **skipped rather than failed**, which reads as agreement.

## 6. Open items

1. **`PHI_REJECTED` has no device refusal.** `SlmCallOutcome` carries it because the backend proxy
   will produce it, but the device would currently classify it as `ENGINE_REJECTED_INPUT`, which is
   the right shape and the wrong name. It belongs with the proxy route in PR-4, where a PHI rejection
   on the SLM boundary first becomes reachable.
2. **No `slm_call_log` table exists.** `SlmCallOutcome`'s docstring says "when that table exists".
   The enum lands now so the vocabulary is settled before the proxy is written; the table and its
   out-of-band write belong to PR-4, on the `write_out_of_band` precedent.
3. **The four audit actions are declared and not emitted.** The seam's audit stage still has only a
   comment at `SlmReadbackUseCase.kt` step 9. Emitting them is later work; the vocabulary agreement
   had to land first, which is the whole point of this PR.
4. **`SlmSuppression.unknownTokens` still has no row.** Computed since PR-1, carried on the answer,
   destined for `slm_readback_sanitizer_activity`.
5. **Six new refusal values have no UI.** Guardrail memo §5.6 requires every refusal to be a
   first-class UI state rather than an error toast. Six values is six states, and the readback
   surface does not exist. PR-7.
6. **`SlmEngine` now has three members and no implementation.** `generate`, `servedModelId`,
   `finishReason`. The interface is growing ahead of its binding, which is deliberate: each member
   exists because a gate at the seam needs it, and the binding in PR-6 has to satisfy all three.
